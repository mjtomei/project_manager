## Rules and limits

- Briefs never share a run of 8 words with the document body (body excludes the metadata header and title line). An issue, pull request or thread post that quotes the body for 30% or more of its word-bearing segments (a pasted draft) is cut where the quote starts; charters and study calls, which predate the document, only lose the passages it quotes. Process documents and templates are attachments, not brief text, in the version committed on or before the document's date.
- Context written after the document is excluded from briefs; see the section above.
- Issue and pull request bodies are their current text, which authors may have edited after opening; task-checkbox and release-target lines, which record progress, are removed from briefs with the PR links nested under them, and so are HTML comments (template guidance).
- Continuation cases: up to 3 per document, spread over eligible headings; prefix at least 100 words, reference 30–4000 words. Boilerplate sections (copyright, IPR, references, addresses, contents) and sections repeated verbatim earlier in the document are never references.
- Heading detection in PDF text (NASA, CERN, HS2) relies on numbered headings and is heuristic; numbered list items can be mistaken for sections.
- PM cases carry `needs_review`: the session map locates candidate provenance, not assent. Reviewed windows are in `pm_case_windows.json`. The Codex history behind plan-delivery is not mounted in this environment.
- Context fetch errors are listed per source in `data/context/<source>.status.json`.
