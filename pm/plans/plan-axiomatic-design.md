# Axiomatic Design Refactoring & Sign-Off Matrix Gate

## Context

An MIT Axiomatic Design (Nam Pyo Suh) analysis of `pm_core` (135 Python modules, 76,595 LOC) found that the system's Design Matrix `{FR} = [A]{DP}` is **not lower-triangular** (coupled design) and exhibits **high Axiom 2 Information Content**:

- **Deferred imports hide two massive cycles**: Of 744 internal import edges, **345 (46.4%) are lazy imports inside function bodies**. While top-level imports show only one cycle (Click CLI subcommand registration), the full runtime import graph collapses **63 of 135 modules — 77.0% of the codebase (58,994 LOC)** — into **two irreducible Strongly Connected Components (SCCs)**:
  1. **Core Engine SCC**: 29 modules (30,106 LOC, 39.3% of `pm_core`) — `paths`, `tmux`, `pane_layout`, `pane_registry`, `git_ops`, `gh_ops`, `backend`, `fake_github`, `push_proxy`, `providers`, `model_config`, `router_route`, `container`, `claude_launcher`, `workspace_trust`, `hook_events`, `prompt_gen`, `spec_gen`, `qa_finalize_prompt`, `behavior_report`, `loop_shared`, `qa_loop`, `signoff`, `runtime_state`, `integration`, `home_window`, `home_window.pr_list`, `tui_pidfile`, `cli.helpers` (including same-layer cycles `fake_github <-> gh_ops`, `backend <-> git_ops`, `tmux <-> pane_layout`, `providers <-> model_config`, and `container <-> router_route <-> claude_launcher`).
  2. **TUI + CLI Surface SCC**: 34 modules (28,888 LOC, 37.7% of `pm_core`) — all 20 `cli/*` command modules fused with 14 active `tui/*` modules (`app`, `auto_start`, `review_loop_ui`, `qa_loop_ui`, `signoff_ui`, `pr_view`, `pane_ops`, `tech_tree`, `screens`, `sync`, `watcher_ui`, `fuzzy_select_cmd`, `model_screen`, `frame_capture`).
- **Not just one misplaced file**: Even if `pm_core/cli/helpers.py` (1,570 LOC, fan-in = 32) is completely excised from the graph, two giant SCCs remain (34 modules + 27 modules).
- **Hidden state coupling beyond imports**:
  - `ProjectManagerApp.__init__` defines **58 `self.*` attributes** mutated directly as a shared blackboard (`app._data` has 7 writer modules and 9 reader modules; `app._review_loops` and `app._qa_loops` are read/written across 4–5 modules).
  - `review_loop_ui.py`'s `_poll_loop_state_inner` acts as the master heartbeat timer for implementation idle polling, `signoff_ui`, `watcher_ui`, `qa_loop_ui`, tech-tree refresh, and auto-merge.
  - **20 distinct modules** call `store.save()` / `store.locked_update()` directly on `project.yaml` (6 CLI modules, 7 TUI modules, 7 core modules — led by 26 sites in `cli/pr.py`).
- **High Information Content (Axiom 2)**:
  - **Monolithic god files**: `qa_loop.py` (6,746 LOC), `cli/pr.py` (4,824 LOC), `prompt_gen.py` (3,028 LOC), `cli/session.py` (2,774 LOC), `tui/auto_start.py` (2,088 LOC), `tui/app.py` (2,045 LOC), `tui/qa_loop_ui.py` (1,788 LOC), `tui/review_loop_ui.py` (1,599 LOC).
  - **Historical regression marker clusters (121 `S##`/`RQ##` markers across 25 files; 85% concentrated in the coupled god-files)**:
    - *QA run identity / clone scoping / instruction-run confusion* (`S90`, `S111`, `S117`, `S120`, `S123`, `S130`, `S131`, `S132` — 30 hits in `tui/qa_loop_ui.py`, 28 in `qa_loop.py`, 16 in `cli/pr.py`, 2 in `paths.py`)
    - *`project.yaml` lock contention & unloadable-file retries* (`RQ37`, `RQ38`, `S44`, `S45`, `S94` — scattered across `tui/qa_loop_ui.py`, `tui/review_loop_ui.py`, `tui/signoff_ui.py`, `tui/sync.py`, `qa_loop.py`, `store.py`)
    - *Tmux grouped-session / pane identity drift* (`S118`, `S121`, `S124`, `S14`, `S16` — duplicated across `tui/app.py`, `cli/helpers.py`, `paths.py`, `pane_registry.py`)

## Design Principles

1. **Zero analyzer code**: Do **not** build a language-specific AST/graph analyzer into `pm_core`. The analysis was produced by simply naming MIT Axiomatic Design in a prompt (with the agent running throwaway inspection commands appropriate to the repo's language). Keeping analysis 100% prompt-driven means it works automatically on **any language and any target repository** (`Python`, `TypeScript`, `Rust`, `Go`, `C++`, mixed repos) with minimal maintenance and minimal Axiom 2 complexity.
2. **State lives in `pm/` (`pm/architecture.md`)**: Just like `pm/notes.txt`, `pm/plans/`, and `pm/qa/`, each managed project stores its living Axiomatic Design analysis in **`pm/architecture.md`** — containing a provenance header (date, git commit, model), the project's FRs, disjoint DPs (mapped to directories/modules), Level-1 (and key Level-2) Design Matrices `[A]`, known cycles/coupling debt, and an FR/DP change log.
3. **Incremental reuse + easy from-scratch regeneration**:
   - Day-to-day workflows (planning, impl, review, sign-off) **reuse and incrementally update** `pm/architecture.md` instead of re-deriving the architecture on every PR.
   - An explicit **regenerate-from-scratch** path runs a fresh, unanchored analysis (without priming the agent with the previous `pm/architecture.md`) and compares/replaces it — making it trivial to take advantage of stronger future models or re-baseline after major refactors.
4. **Automatic onboarding on new projects**: `pm init` / `pm guide` automatically includes `pm/architecture.md` bootstrap — analyzing existing repositories on init, or seeding FRs and DPs from the first plan on greenfield repositories so `[A]` starts lower-triangular from day one.
5. **Sign-off stewardship & anti-gaming**: Every sign-off run audits the PR against `pm/architecture.md` — checking for new upper-triangular `*` coupling, hidden state coupling, unmapped modules, or "gaming" the matrix by merging unrelated DPs — includes an **Architecture / Design Matrix** section in `$CAP/report.html`, routes coupling regressions to `SIGNOFF_IMPL`, and keeps `pm/architecture.md` updated as PRs land.
6. **Replace scattered regression patches with single-source-of-truth invariants**: Each refactoring PR targets not only import cycles (Axiom 1) but also the underlying Axiom 2 root cause behind the `S##`/`RQ##` regression marker clusters, keeping every regression test green while deleting duplicated workaround logic.

## Constraints

- **No analyzer code in `pm_core`**: Only lightweight state/file plumbing (same pattern as `pm_core/notes.py`) and prompt templates. No Python-specific AST parsers or custom static analyzers added to `pm_core`.
- **Works for both in-repo `pm/` and standalone `--dir` `pm/`**: `pm/architecture.md` lives inside the project's `pm` state root (`root / "architecture.md"`).
- **Sign-off remains a router, never a code editor**: The sign-off agent audits coupling and records any required `pm/architecture.md` update in its report/notes without editing target repo code; coupling regressions route to `SIGNOFF_IMPL`.
- **No big-bang rewrite**: Every refactoring PR keeps the full `pytest` suite green (including all `S##`/`RQ##` regression tests) and preserves CLI commands, TUI keybindings, `project.yaml` compatibility, and `tests/test_tui_imports.py` import paths.
